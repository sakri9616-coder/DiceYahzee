# 2人対戦の実装計画（2026-10-16）

## 着手時の調査結果

- Unity 6000.3.25f1。対局の現行ルールは `Assets/Scripts/Core/ScoreDuel.cs` の `ScoreRules` / `ScoreForecast`、画面と入力は `Assets/Scripts/Presentation/GameFlow.ScoreDuel*.cs` にある。
- CPU戦の `ScoreDuel` は敵の手を先に作る設計で、二人分の入力を受ける対戦状態機械には流用しにくい。オフライン戦はそのまま維持する。
- `Packages/manifest.json` に Multiplayer Services と Netcode for GameObjects は未導入。`ProjectSettings.asset` の `cloudProjectId` は空で、Unity Cloud プロジェクトも未作成。

## 仕様と境界

1. Unity を使わない `VersusDuel` が二人のHP、ダイス、保持、残り振り直し、役の使用、持越、ラウンドと勝敗を管理する。既存の `ScoreRules` とダメージ計算の共通部分を使う。ダイスの乱数源はホスト側にだけ置く。
2. 1ラウンドで両者がそれぞれ最大2回振り直し（ヤッツィー成立の次ラウンドは3回）、役と持越を提出する。双方の提出後にホストが、チャンス宣言時の被害の受け手の入れ替えを反映した同時ダメージと勝敗を確定する。提出後の追加操作は受け付けない。
3. 通信要求は「保持マスクと振り直し」「役と持越の提出」に限る。各要求にプレイヤー・ラウンド・単調増加する操作番号を付け、ホストが接続ID、手番、段階、残り回数、役の使用状態、番号を検証する。結果の点数や出目をゲストから受け取らない。互いの初回の出目はラウンド開始時に公開し、振り直し中は伏せ、双方が振り直しを終えた時点で最終の出目を揃って公開する。提出した役と持越だけは双方提出まで伏せる。
4. ホストの確定状態を操作ごとに両クライアントへ配信する。切断時は進行を止め、残った側へ中断を表示する。自動再接続・ホスト移譲は行わない。
5. Unity Multiplayer Services の非公開2人セッションを Relay 接続で作り、匿名認証、コード参加を行う。Netcode for GameObjects はセッションのゲーム通信に使い、専用サーバーを置かない。自動マッチング、ランキング、アカウント登録は追加しない。
6. 対局中の持越は発射時に確定する。被害は通常どおり共通軽減を適用し、持越側も通常の被害計算を行う。生存して次ラウンドへ進んだ場合に限り、出目と保持を引き継ぐ。CPU戦にも同じ被害計算を適用する。
7. 対戦画面は現行の役レールとダイス表現を引き継ぐ。持越は中央で状態を示し、選択時だけ短い粒子演出を出す。被害の数値と残HPの変化はHPバー周辺へまとめる。

## 実装・確認順

1. パッケージ導入とUnity Cloudプロジェクト作成・紐付け。
2. `VersusDuel` と不正入力・重複入力・二人決着のEditModeテスト。
3. Relay/セッション/NGO通信と二人用画面。二つの実行版を用いて招待から勝敗まで、切断を確認。
4. 持越とHPの演出調整、PlayModeと実画面確認。既存オフライン回帰を実行。

## 実装で確定した構成

- `VersusDuel` はUnityと通信SDKを参照しない。ホストだけが乱数と状態更新を持ち、ゲストはラウンド番号・単調増加する操作番号・保持マスク・役・持越の選択を送る。ホストは接続元IDと行動条件を確認し、拒否した操作では状態を進めない。
- 両者の初回の出目はラウンド開始時に公開し、振り直しの結果は双方の振り直しが終わるまで隠す。双方が振り直しを終えると最終の出目を揃って公開する。提出した役・得点・持越と、その役を使った事実は双方提出まで相手向けスナップショットから隠す。
- ラウンド決着は双方の提出後に同時処理する。次ラウンドは両クライアントが画面をクリックした後にホストが進める。切断した対局は続行せず、残った側に中断を表示する。
- CPU戦のルールは維持する。持越も通常の共通軽減を適用する計算へ統一し、生存した場合に限り出目を次ラウンドへ引き継ぐ。対局中に使える持越は各自1回。
- オンライン画面では左右の役レール、中央の持越、役倍率による得点、HPバー左の減少量、右側の下フリック・ホイールガイドを使う。攻撃時はダイスの衝突とダメージ量による4段階の輪・放射線を再生する。

テストと実行版の正確な範囲は `docs/TEST_REPORT.md` §21に記録する。

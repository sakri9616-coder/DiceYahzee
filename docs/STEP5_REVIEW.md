# 第4回（2026-10-10）— 人間プレイヤーのプレイテストを受けて

第1〜3回は音声・UI・文書・数値バランスが中心で、**「ルールの中身」「操作の流れそのもの」「演出」を正面から問うてはいなかった。**
その結果、バランス数値の改善に注力した末に、その数値が**ゲームとしての魅力の証明になっていないこと**に気づかなかった。
今回は一次情報（人間プレイヤーの指摘4件）を契機に、中心ルールを問うた。

## 4.1 実施

| 系統 | 手法 | 出力 |
| --- | --- | --- |
| Step 5 Preview（StepFun 公式 API `api.stepfun.ai/v1`、第4回） | 構造分析を自ら検証するよう要求 | `logs/step5-round4-out.txt`（finish=stop、15,731トークン） |
| game-critic（LongCat） | コード行・画面・数値の根拠を義務付け | 独立レポート |
| 参考4作品の調査 | 公式資料のみ採用、未確認は未確認と明記 | Dice Throne / Dicey Dungeons / Slice & Dice / Balatro |

3系統とも同じ4点に収束した。詳細と処置は `docs/DESIGN_REVIEW_V2.md` に記録した。

## 4.2 3系統の合意

1. **攻守分割が「攻撃合計という1本のスカラー」に潰れている。** `SumMask` は合計しか返さず、
   同じ攻撃合計なら30通りの分割は完全に等価。**ダイスの構成がゲーム内価値に現れない。**
2. **役（パターン）が存在せず、達成感も振り直しの目標も無い。**
3. **振り直しと分割のモード往復がプレイヤーの意図を破壊している。** `EnterSplitMode()` が必ず
   `ResetSplitToDefault()` を呼ぶため、振り直すたびに手動の分割が「上位2個」にリセットされる。
4. **戦闘結果の内訳が表示されず、演出も無い。**

Step 5 の総合判定は CONDITIONAL、自己採点は「**現状の核は標準ヤッツィーや Dice Throne に勝てない（10点中0点）**」。

## 4.3 本批評だけが見つけたもの

- `MatchEngine.PlayerKept` は**全 false 初期化**されるため、何もクリックせず「振り直す」を押すと
  **手の5個すべてを確認なしで捨てられる。** 3系統とも未指摘だった。
- 「相手の型に応じて攻守を切り替えます」というルール本文のコツは、判断材料が
  全て非公開なので**実行できない**（game-critic の指摘）。

## 4.4 処置（`docs/DESIGN_REVIEW_V2.md` §5 に全15件）

ACCEPT 13 / DEFER 1 / 前提の訂正 1。**中心ルール（攻守分割のみ）の維持はやめ、**

## 5.2 質問1（「遊ぶ理由」）に対する批評の回答

第4回批評では「現行の核は標準ヤッツィーや Dice Throne に勝てない（自己採点 0/10）」だった。
第5回批評は **「説明できる」と回答した**。回答に使った場面:

> 自分HP 9 / 相手HP 14、ラウンド4、振り直し残り2、手元 **2, 2, 3, 4, 5**（既定は上位2個を攻撃）。
> - 既定のまま: 攻撃9・守り7、ストレート不成立、相手守護10なら貫通0 → ダメージ0。
> - **2, 3, 4, 5 を攻撃に回す**: 攻撃14・守り2、**4連続ストレート成立**。相手守護10なら貫通4＋陣形5＝**9**、
>   相手守護14でも貫通0＋陣形5＝**5**。

この判断が**相手の守護を貫通できないときも確定ダメージを「買う」**ものであり、
「守りを捨てて相手の守備を無力化する」か「守りを厚くして通ったときの大きさに賭ける」かという、
**ダイスの目ではなく構成を基準にしたリスク選好**だと説明している。
標準ヤッツィーには「相手の守護」という変数が存在しないため発想が生まれない、と述べている
（Dice Throne については「詳細は未確認」と明記した上で比較）。

**MiMo の判定**: この説明は第4回批評の結論を覆すに足る。
**コアルールの差し替えは妥当だった**と結論する。ただし「説明できる」ことと
「人間にとって面白いか」は別物であり、後者は今も未測定（§5.3 V5-5）。

### V5-6（先手勝率）— REJECT。批評の前提が一次ファイルと食い違う

### V5-8（同時公開と非公開の矛盾）— REJECT、ただし部分ACCEPT

「同時公開するなら相手情報が見えるはず」という指摘は、
本作が**同時秘匿コミット**（お互いに決めた瞬間は隠し、同時に開く）であることを踏まえれば矛盾ではない。
ポーカーのショーダウンと同じ構造である。

**ただし批評の (b)「なぜ非公開なのかがルールから読み取れない」は正しく、これはドキュメントの欠陥**である。
`GAME_DESIGN.md` §2.2 に理由を明記した。

### V5-9（既定動作が核メカニクスを隠す）— ACCEPT（記録、未実装）

既定が「上位2個を攻撃」なので、**何も操作しないと陣形はほぼ成立しない**。
初見プレイヤーは「このゲームの主体は陣形だ」と気づくまでに操作を要する。
これは既存の「チュートリアル未実施（DEFER）」と重なるが、
**チュートリアルの有無ではなく既定値の設計に起因する**ため、別個の問題として記録する。

### V5-10（「最高の1つだけ」条文が死語）— ACCEPT（事実として記録）

5d6 では **スリーカインド（同一目3個）と 4連続ストレート（4つの異なる目）は同時に成立しない**。
スリーカインドが成立するには同一目の3個が必要で、その場合4つの異なる連続目は作れない。
したがって「1手に成立しうる陣形は最も高いもの1つだけ」は**現在冗長な条文**である。
ただし V5-4 で陣形を増やせば条文が必要になるため、**削除はしない**。
`GAME_DESIGN.md` §2.3 にこの事実を明記した。

### V5-11（振り直し2回が多すぎる）— DEFER
